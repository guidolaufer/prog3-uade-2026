Ejercicio 1 — Decodificar mensaje con árbol de Huffman

Decodifique el siguiente mensaje usando el árbol de Huffman dado:

Paso 1 — Leer el árbol y armar la tabla de códigos

El árbol de Huffman del parcial asigna un código binario a cada carácter. 0 = ir a la izquierda, 1 = ir a la derecha. Los nodos hoja (con letra) son los caracteres.

Paso 2 — Leer el árbol del enunciado

¿Cómo leer un árbol de Huffman? Empezás en la raíz. Por cada bit del mensaje: si es 0 bajás a la izquierda, si es 1 bajás a la derecha. Cuando llegás a una hoja (nodo con letra), ese es el carácter decodificado. Volvés a la raíz y seguís con el siguiente bit.

Paso 3 — Decodificar el mensaje

Mensaje: 1011101110011101010100110011101010111111110000100010110100101110101001111010111011100111010100000001010001111010

Recorremos el árbol con cada bit:
101 → i
110 → (seguimos)...

Decodificación completa bit a bit:
10111 → d
011   → n
100   → b (esperar otro bit)
...

NOTA: La decodificación exacta depende del árbol específico del enunciado.
El proceso siempre es el mismo: recorrer el árbol bit a bit hasta llegar a una hoja.

Paso 4 — Procedimiento general (cómo lo hacés en el parcial)

1. Armá la tabla de códigos leyendo el árbol (como la tabla de arriba)

2. Tomá los bits del mensaje de a uno:
   - Cada vez que llegás a una hoja → escribí el carácter → volvé a la raíz
   - Si no llegaste a una hoja → seguí leyendo bits

Ejemplo con código {a=0, b=10, c=11}:
Mensaje: 010110
  bit 0 → llego a hoja 'a' → escribo 'a', vuelvo a raíz
  bit 1 → rama derecha
  bit 0 → llego a hoja 'b' → escribo 'b', vuelvo a raíz
  bit 1 → rama derecha
  bit 1 → llego a hoja 'c' → escribo 'c'
Resultado: "abc" ✅
Regla para el parcial: el árbol de Huffman es un código prefijo — ningún código es prefijo de otro. Eso garantiza que la decodificación es unívoca (no hay ambigüedad). Siempre recorrés el árbol desde la raíz para cada carácter nuevo.

Ejercicio 2 — Análisis de complejidad temporal de Divide & Conquer

Tomando como ejemplo el algoritmo Merge Sort, haga un análisis matemático de complejidad temporal para peor caso de los algoritmos de divide y conquista.

Estructura general de un algoritmo D&C

Todo algoritmo D&C sigue este patrón:

función resolver(problema de tamaño n):
  si n ≤ caso_base:
    resolver directamente → costo O(1)
  sino:
    dividir en a subproblemas de tamaño n/b    → costo O(f(n))
    llamar recursivamente a cada subproblema
    combinar los a resultados                  → costo O(f(n))

Recurrencia general:
  T(n) = a · T(n/b) + f(n)

donde:
  a = número de subproblemas
  b = factor por el que se reduce el tamaño
  f(n) = costo de dividir + combinar

Aplicado a MergeSort

MergeSort(A[0..n-1]):
  si n == 1: return                           → O(1)
  mitad = n/2
  MergeSort(A[0..mitad-1])                    → T(n/2)
  MergeSort(A[mitad..n-1])                    → T(n/2)
  Merge(A[0..mitad-1], A[mitad..n-1])         → O(n)

Parámetros:
  a = 2  (dos llamadas recursivas)
  b = 2  (cada mitad tiene n/2 elementos)
  f(n) = O(n)  (merge recorre todos los elementos)

Recurrencia: T(n) = 2·T(n/2) + O(n)

Resolución por árbol de recursión

Nivel 0:  n           → costo: n
         / \
Nivel 1: n/2  n/2     → costo: n/2 + n/2 = n
        /\   /\
Nivel 2: n/4 (×4)    → costo: 4 × n/4 = n
...
Nivel k: n/2^k (×2^k) → costo: 2^k × n/2^k = n

¿Cuántos niveles hay?
  El caso base es n/2^k = 1 → k = log₂(n)

Total de niveles: log₂(n)
Costo por nivel: n (siempre)

T(n) = n × log₂(n) = O(n log n)

Resolución por Teorema Maestro

T(n) = 2·T(n/2) + n

Parámetros: a=2, b=2, f(n)=n
Calcular: log_b(a) = log₂(2) = 1
Comparar: f(n) = n = n^1 = n^(log_b a)

→ Caso 2 del Teorema Maestro:
  f(n) = Θ(n^(log_b a)) = Θ(n^1)

  T(n) = Θ(n^(log_b a) · log n) = Θ(n · log n)

Complejidad: T(n) = O(n log n) ✅

Verificación intuitiva

Para n = 8 elementos:
  Nivel 0: 1 llamada, merge de 8 → 8 comparaciones
  Nivel 1: 2 llamadas, merge de 4 → 4+4 = 8 comparaciones
  Nivel 2: 4 llamadas, merge de 2 → 2+2+2+2 = 8 comparaciones
  Nivel 3: 8 hojas, tamaño 1 → 0 comparaciones (caso base)

  Niveles: log₂(8) = 3
  Total: 3 × 8 = 24 comparaciones = n·log₂(n) ✅
Respuesta para el parcial: T(n) = 2T(n/2) + O(n) → por Teorema Maestro, Caso 2 → T(n) = O(n log n). Se puede demostrar por árbol de recursión: log₂(n) niveles × costo O(n) por nivel = O(n log n).

¿Qué es DFS?

DFS (Depth-First Search = Búsqueda en Profundidad): explorás lo más profundo posible antes de retroceder. Usás un stack (o recursión). Marcás cada nodo como visitado al explorarlo.

Algoritmo DFS paso a paso

DFS(grafo G, nodo inicio):
  marcar inicio como VISITADO
  para cada vecino v de inicio (en orden alfabético):
    si v NO fue visitado:
      DFS(G, v)      ← ir más profundo primero

Invariante: siempre exploramos el vecino no visitado
más pequeño (alfabético) antes de retroceder.

Traza completa desde nodo A

Visitados: []   Stack de recursión: []

1.  Visitar A → vecinos no visitados: B, D, E, G
    Ir al primero: B
    A→B (arista 1)

2.  Visitar B → vecinos no visitados: D, M  (A ya visitado)
    Ir al primero: D
    B→D (arista 2)

3.  Visitar D → vecinos no visitados: C, F, H  (A,B ya visitados)
    Ir al primero: C
    D→C (arista 3)

4.  Visitar C → vecinos no visitados: F, H  (D ya visitado)
    Ir al primero: F
    C→F (arista 4)

5.  Visitar F → vecinos no visitados: (ninguno, C y D ya visitados)
    BACKTRACK a C

6.  C continúa → vecino no visitado: H
    C→H (arista 5)

7.  Visitar H → vecinos no visitados: E  (C,D ya visitados)
    H→E (arista 6)

8.  Visitar E → vecinos no visitados: G, J  (A,H ya visitados)
    Ir al primero: G
    E→G (arista 7)

9.  Visitar G → vecinos no visitados: I, J  (A,E ya visitados)
    Ir al primero: I
    G→I (arista 8)

10. Visitar I → vecinos no visitados: L, M  (G ya visitado)
    Ir al primero: L
    I→L (arista 9)

11. Visitar L → vecinos no visitados: K, M  (I ya visitado)
    Ir al primero: K
    L→K (arista 10)

12. Visitar K → vecinos no visitados: (ninguno, J no visitado aún)
    K→J? → J no visitado
    K→J (arista 11)

13. Visitar J → vecinos no visitados: (E,G,K ya visitados)
    BACKTRACK a K → BACKTRACK a L

14. L continúa → M no visitado
    L→M (arista 12)

15. Visitar M → vecinos no visitados: B ya visitado, I ya visitado
    BACKTRACK a L → BACKTRACK a I → ...

16. Continuar backtrack hasta E → J ya visitado
    BACKTRACK a G → BACKTRACK a E
    E continúa → J ya visitado → BACKTRACK a H
    BACKTRACK completo hasta A

17. A continúa → D ya visitado, E ya visitado, G ya visitado
    DFS completo ✅

Orden de visita de nodos:
A → B → D → C → F → H → E → G → I → L → K → J → M

Orden de aristas (en que se trazan):
1: A-B    2: B-D    3: D-C    4: C-F    5: C-H
6: H-E    7: E-G    8: G-I    9: I-L   10: L-K
11: K-J  12: L-M
Las aristas "de árbol" son las 12 aristas trazadas en el orden anterior. Las demás aristas del grafo son "aristas de retroceso" (back edges) — conectan un nodo con un ancestro ya visitado. En DFS no dirigido, todas las aristas no usadas son back edges.

Ejercicio 4 — Recorrido Preorden del árbol

Recorra por preorden el siguiente árbol e indique el orden de visita de sus vértices o nodos.

Árbol del enunciado

¿Qué es el recorrido Preorden?

Preorden (Pre-Order): Raíz → Izquierda → Derecha
Visitás el nodo ANTES de visitar sus hijos. Primero la raíz, luego el subárbol izquierdo completo, luego el subárbol derecho completo.

Comparación con los otros recorridos:
• Preorden: Raíz → Izq → Der
• Inorden: Izq → Raíz → Der (da los nodos en orden si es BST)
• Postorden: Izq → Der → Raíz

Traza paso a paso del preorden

Estructura del árbol:
         1
       /   \
      2     6
    /   \   / \
   7    10  15  17
  / \  / \   \
 20 22 29 30  56

Algoritmo preorden(nodo):
  visitar(nodo)           ← PRIMERO el nodo
  preorden(hijo_izq)      ← luego el subárbol izquierdo
  preorden(hijo_der)      ← luego el subárbol derecho

🎯 Tips para el Parcial

Ejercicio tipo Huffman

1. Leer el árbol del enunciado de arriba hacia abajo.
2. Armar la tabla: cada hoja = un carácter. Su código = secuencia de 0s y 1s del camino desde la raíz.
3. Para decodificar: bit a bit, si 0 → izquierda, si 1 → derecha. Al llegar a hoja → escribir carácter, volver a raíz.
4. Nunca hay ambigüedad — Huffman es código prefijo.

Ejercicio tipo Complejidad D&C

1. Identificar a (nº subproblemas) y b (factor de división).
2. Identificar f(n) (costo de dividir/combinar).
3. Calcular log_b(a) y comparar con f(n).
4. Aplicar el caso correcto del Teorema Maestro.
5. Alternativamente: dibujar árbol de recursión y contar trabajo por nivel × nº niveles.

Ejercicio tipo DFS/BFS

1. DFS: ir siempre al vecino más profundo no visitado. Si hay empate → orden alfabético. Usar stack o recursión.
2. BFS: visitar todos los vecinos del nivel actual antes de bajar. Usar cola (queue).
3. Marcar nodos visitados para no repetir.
4. Las aristas que "descubren" nuevos nodos son las aristas del árbol DFS/BFS.

Ejercicio tipo Recorrido de árbol

Memorizar con mnemónico:
• PREorden = PREprimero la raíz (Raíz-Izq-Der)
• INorden = la raíz va al medio (Izq-Raíz-Der)
• POSTorden = la raíz va al final/atrás (POSTerior) (Izq-Der-Raíz)

Para resolver: hacerlo recursivamente. En preorden, siempre visitás el nodo actual ANTES de sus hijos.
