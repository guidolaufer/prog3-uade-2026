💰 Greedy — Ejercicio 1: Cambio de Monedas

GREEDY

Problema A: Dar cambio de $87 usando la menor cantidad de monedas del sistema argentino: {50, 25, 10, 5, 1}.

Solución Greedy — siempre tomar la moneda más grande posible

Monto restante: 87
  Paso 1: 87 ≥ 50 → tomar 1 moneda de $50. Resta: 37
  Paso 2: 37 ≥ 25 → tomar 1 moneda de $25. Resta: 12
  Paso 3: 12 ≥ 10 → tomar 1 moneda de $10. Resta:  2
  Paso 4:  2 <  5 → saltar
  Paso 5:  2 ≥  1 → tomar 1 moneda de $1.  Resta:  1
  Paso 6:  1 ≥  1 → tomar 1 moneda de $1.  Resta:  0

Resultado: [50, 25, 10, 1, 1] = 5 monedas ✅

Problema B: Dar cambio de $11 con monedas {1, 3, 4}. ¿Greedy es óptimo?

Greedy (mayor moneda primero):
  11 ≥ 4 → tomar 4. Resta: 7
   7 ≥ 4 → tomar 4. Resta: 3
   3 ≥ 3 → tomar 3. Resta: 0
Resultado Greedy: [4, 4, 3] = 3 monedas ✅ (óptimo en este caso)

Pero para cambio de 6 con {1, 3, 4}:
Greedy: 4 + 1 + 1 = 3 monedas
Óptimo: 3 + 3   = 2 monedas ← Greedy falla aquí ❌
Conclusión: Greedy funciona para el sistema de monedas estándar (50, 25, 10, 5, 1) porque tiene la propiedad de que siempre conviene tomar la denominación mayor. Con denominaciones arbitrarias, puede fallar. Para garantizar óptimo con cualquier denominación → usar Programación Dinámica.

🔙 Backtracking — Ejercicio 5: N-Reinas

BACKTRACKING

Problema: Colocar 4 reinas en un tablero 4×4 de modo que ninguna se ataque.

Dos reinas se atacan si están en la misma fila, columna o diagonal.

Representación: sol[i] = columna de la reina en la fila i

Árbol de búsqueda (fila=nivel, columna=valor):

Fila 1, col 1 → sol=[1,_,_,_]
  Fila 2, col 1 → ATAQUE COLUMNA ✗
  Fila 2, col 2 → ATAQUE DIAGONAL ✗  (|2-1|=|2-1|=1)
  Fila 2, col 3 → OK → sol=[1,3,_,_]
    Fila 3, col 1 → ATAQUE DIAGONAL ✗ (|3-1|=|1-3|=2)
    Fila 3, col 2 → ATAQUE DIAGONAL ✗ (|3-1|=|2-3|≠ wait: |2-3|=1≠2... 
                    col vs fila: reina(1,1) y (3,2):|3-1|=2,|2-1|=1 → no diagonal
                    reina(2,3) y (3,2):|3-2|=1,|2-3|=1 → DIAGONAL ✗
    Fila 3, col 3 → ATAQUE COLUMNA ✗ (col 3 ocupada)
    Fila 3, col 4 → reina(1,1)+(3,4):|3-1|=2,|4-1|=3 OK
                    reina(2,3)+(3,4):|3-2|=1,|4-3|=1 → DIAGONAL ✗
    → BACKTRACK a Fila 2
  Fila 2, col 4 → OK → sol=[1,4,_,_]
    Fila 3, col 1 → reina(1,1)+(3,1): COLUMNA ✗
    Fila 3, col 2 → reina(1,1)+(3,2):|3-1|=2,|2-1|=1 OK
                    reina(2,4)+(3,2):|3-2|=1,|2-4|=2 OK → sol=[1,4,2,_]
      Fila 4, col 1 → reina(1,1)+(4,1): COLUMNA ✗
      Fila 4, col 2 → reina(3,2)+(4,2): COLUMNA ✗
      Fila 4, col 3 → reina(1,1)+(4,3):|4-1|=3,|3-1|=2 OK
                      reina(2,4)+(4,3):|4-2|=2,|3-4|=1 OK
                      reina(3,2)+(4,3):|4-3|=1,|3-2|=1 → DIAGONAL ✗
      Fila 4, col 4 → reina(2,4)+(4,4): COLUMNA ✗
      → BACKTRACK
    Fila 3, col 3 → reina(2,4)+(3,3):|3-2|=1,|3-4|=1 → DIAGONAL ✗
    Fila 3, col 4 → reina(2,4)+(3,4): COLUMNA ✗
    → BACKTRACK

Fila 1, col 2 → sol=[2,_,_,_]
  ...
  Fila 2, col 4 → OK → sol=[2,4,_,_]
    Fila 3, col 1 → reina(2,4)+(3,1):|1|=1,|3-1|=3 OK ✓
                    reina(1,2)+(3,1):|2|=2,|1-2|=1 → no diagonal
                    → sol=[2,4,1,_]
      Fila 4, col 3 → verificar todas → OK! ✅

SOLUCIÓN ENCONTRADA: sol=[2,4,1,3]

Visualización del tablero solución

     Col: 1   2   3   4
Fila 1:   .   Q   .   .    ← Reina en (1,2)
Fila 2:   .   .   .   Q    ← Reina en (2,4)
Fila 3:   Q   .   .   .    ← Reina en (3,1)
Fila 4:   .   .   Q   .    ← Reina en (4,3)

Verificación:
  Columnas: 2,4,1,3 → todas distintas ✓
  Diagonales: |1-2|≠|2-4|, |1-3|≠|2-1|, etc. → ningún ataque ✓

Función de validación

esValido(sol, fila, col):
  para i desde 1 hasta fila-1:
    si sol[i] == col:          → misma columna ✗
      return false
    si |sol[i] - col| == |i - fila|: → misma diagonal ✗
      return false
  return true
¿Cuántas soluciones tiene el tablero 4×4? Solo 2 (y sus reflejos): [2,4,1,3] y [3,1,4,2]. Para 8×8: 92 soluciones. Para N grande, escala como O(N!).

🔙 Backtracking — Ejercicio 6: Suma de Subconjuntos

BACKTRACKING

Problema: Encontrar todos los subconjuntos de {3, 5, 6, 7} cuya suma sea exactamente 15.

Árbol de decisión: en cada nivel decidimos INCLUIR o NO al elemento.
Poda: si suma parcial > 15, no seguir.

Nivel 0 (incluir 3?):
  SÍ → suma=3
    Nivel 1 (incluir 5?):
      SÍ → suma=8
        Nivel 2 (incluir 6?):
          SÍ → suma=14
            Nivel 3 (incluir 7?):
              SÍ → suma=21 > 15 → PODAR ✗
              NO → suma=14 ≠ 15 → no es solución
          NO → suma=8
            Nivel 3 (incluir 7?):
              SÍ → suma=15 ✅ SOLUCIÓN: {3,5,7}
              NO → suma=8 ≠ 15
      NO → suma=3
        Nivel 2 (incluir 6?):
          SÍ → suma=9
            Nivel 3 (incluir 7?):
              SÍ → suma=16 > 15 → PODAR ✗
              NO → suma=9 ≠ 15
          NO → suma=3
            Nivel 3 (incluir 7?):
              SÍ → suma=10 ≠ 15
              NO → suma=3 ≠ 15
  NO → suma=0
    Nivel 1 (incluir 5?):
      SÍ → suma=5
        Nivel 2 (incluir 6?):
          SÍ → suma=11
            Nivel 3 (incluir 7?):
              SÍ → suma=18 > 15 → PODAR ✗
              NO → suma=11 ≠ 15
          NO → suma=5
            Nivel 3 (incluir 7?):
              SÍ → suma=12 ≠ 15

🔙 Backtracking — Ejercicio 7: Coloreo de Grafos

BACKTRACKING

Problema: Colorear los nodos del grafo con 3 colores de modo que ningún par de nodos adyacentes tenga el mismo color.

Grafo:  1 — 2
        |   |
        3 — 4 — 5

Aristas: (1,2), (1,3), (2,4), (3,4), (4,5)

Nodo 1: probar color R → sol={1:R}
  Nodo 2: adj(2)={1:R} → probar G (≠R) → sol={1:R,2:G}
    Nodo 3: adj(3)={1:R} → probar G → sol={1:R,2:G,3:G}
      Nodo 4: adj(4)={2:G,3:G} → probar R → sol={...,4:R}
        Nodo 5: adj(5)={4:R} → probar G → sol={...,5:G} ✅

SOLUCIÓN: {1:R, 2:G, 3:G, 4:R, 5:G}

Verificación:
  (1,2): R≠G ✓  (1,3): R≠G ✓  (2,4): G≠R ✓
  (3,4): G≠R ✓  (4,5): R≠G ✓
3-colorabilidad es un problema NP-completo. Backtracking lo resuelve, pero en el peor caso explora todos los coloreados posibles: O(k^n) donde k=colores, n=nodos. La poda (verificar conflictos antes de avanzar) lo hace práctico para grafos pequeños.

🧠 Quiz — Greedy & Backtracking

Intentá responder antes de ver la solución.

¿Qué diferencia hay entre Greedy y Backtracking para el mismo problema?
Greedy toma una decisión y nunca la revisa — elige el candidato localmente óptimo y avanza. Backtracking prueba una opción, avanza, y si no funciona vuelve atrás a probar otra. Greedy es más rápido (O(n log n) típico) pero no siempre da el óptimo. Backtracking siempre encuentra la solución óptima (o todas las soluciones) pero puede ser exponencial.
¿Por qué en Selección de Actividades se ordena por tiempo de FIN y no de inicio?
Ordenar por tiempo de fin maximiza las actividades que podemos incluir. La actividad que termina antes "libera" el salón más pronto, dejando más espacio para otras actividades. Si ordenáramos por inicio, podríamos tomar una actividad que empieza temprano pero termina tarde, bloqueando muchas otras. Ordenar por fin es la elección greedy que tiene propiedad greedy demostrable: siempre forma parte de alguna solución óptima.
¿Qué es la propiedad "greedy choice property"?
Es la propiedad que garantiza que el algoritmo greedy produce la solución óptima: la elección localmente óptima en cada paso siempre es parte de alguna solución globalmente óptima. Se demuestra por contradicción (argumento de intercambio): se asume que hay una solución óptima que no incluye la elección greedy, y se muestra que podés "intercambiar" para incluirla sin empeorar la solución. Si esta propiedad no se cumple, Greedy puede fallar.
¿Cómo funciona la poda en Backtracking y cómo mejora la performance?
La poda corta ramas del árbol de búsqueda cuando se detecta que ninguna solución en esa rama puede ser válida u óptima. Tipos de poda: (1) Poda de factibilidad: la solución parcial ya viola alguna restricción → cortar. (2) Poda de optimalidad (branch & bound): la solución parcial no puede superar la mejor encontrada hasta ahora → cortar. Sin poda, backtracking = fuerza bruta = O(2^n) o O(n!). Con buena poda, puede resolver instancias prácticas en tiempo razonable.
¿Cuántas soluciones tiene el problema de 8-reinas?
El problema de 8-reinas tiene 92 soluciones (sin contar simetrías y rotaciones; si contamos solo soluciones fundamentalmente distintas son 12). Backtracking las encuentra todas explorando el árbol de decisión, podando cada vez que dos reinas se atacan. Sin poda, habría 8^8 = 16.777.216 posibles configuraciones. Con poda, se exploran ~15.720 nodos del árbol.
¿Cómo se representa un estado en Backtracking?
Un estado en backtracking se representa como una solución parcial: los valores asignados hasta el momento más la posición actual. En N-Reinas: sol[1..fila_actual] donde sol[i]=columna de la reina en fila i. En suma de subconjuntos: conjunto actual + suma parcial + índice actual. La clave es que el estado capture toda la información necesaria para decidir si agregar un candidato es válido, y para hacer backtrack (deshacer la última decisión).
