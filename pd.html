📌 Ejercicio 1 — Fibonacci: recursión vs PD

Problema: Calcular el 6.º número de Fibonacci. Comparar la recursión ingenua con PD.

Método 1: Recursión ingenua — O(2ⁿ)

fib(6) = fib(5) + fib(4)
fib(5) = fib(4) + fib(3)   ← fib(4) se calcula 2 veces
fib(4) = fib(3) + fib(2)   ← fib(3) se calcula 3 veces
fib(3) = fib(2) + fib(1)   ← fib(2) se calcula 5 veces
fib(2) = fib(1) + fib(0) = 1
fib(1) = 1, fib(0) = 0

Árbol de llamadas para fib(6): 25 llamadas a función
Para fib(50): ~2^50 = 10^15 llamadas → inviable

Método 2: PD Bottom-Up — O(n)

Ecuación de recurrencia: dp[n] = dp[n-1] + dp[n-2]
Casos base: dp[0] = 0, dp[1] = 1

Llenado de tabla:
  dp[0] = 0
  dp[1] = 1
  dp[2] = dp[1] + dp[0] = 1 + 0 = 1
  dp[3] = dp[2] + dp[1] = 1 + 1 = 2
  dp[4] = dp[3] + dp[2] = 2 + 1 = 3
  dp[5] = dp[4] + dp[3] = 3 + 2 = 5
  dp[6] = dp[5] + dp[4] = 5 + 3 = 8 ✅

Solo 6 operaciones. Para n=50: 50 operaciones vs 10^15

Método 3: PD con Memoización (top-down) — O(n)

memo = {}  ← diccionario para guardar resultados

fib_memo(n):
  si n en memo → retornar memo[n]  (ya calculado)
  si n == 0 → retornar 0
  si n == 1 → retornar 1
  resultado = fib_memo(n-1) + fib_memo(n-2)
  memo[n] = resultado  ← guardar para futuras llamadas
  retornar resultado

fib_memo(6):
  fib_memo(5) → fib_memo(4) → ... → calcula hasta base
  fib_memo(4) ya está en memo → retorna directo
  Total: cada valor se calcula UNA SOLA VEZ
Diferencia clave: Bottom-up llena la tabla de menor a mayor (iterativo). Memoización calcula top-down solo los subproblemas necesarios (recursivo con caché). Ambos son O(n).

📌 Ejercicio 2 — Mochila 0/1 (el ejemplo clásico de PD)

Problema: Mochila con capacidad W=6. Items (NO se pueden fraccionar, solo tomar o no):

ItemPesoValor
1 (laptop)26
2 (cámara)210
3 (joya)312

Ecuación de recurrencia

dp[i][w] = máximo valor usando los primeros i items con capacidad w

Si peso[i] > w:
  dp[i][w] = dp[i-1][w]          ← item no cabe, no tomarlo

Si peso[i] ≤ w:
  dp[i][w] = max(
    dp[i-1][w],                   ← NO tomar el item i
    dp[i-1][w - peso[i]] + val[i] ← SÍ tomar el item i
  )

Llenado de tabla (fila=items, columna=capacidad)

Item \ W0123456
0 (ninguno)0000000
1 (p=2,v=6)0066666
2 (p=2,v=10)001010161616
3 (p=3,v=12)001012162222

Traza de cálculo — fila 3 (item joya, p=3, v=12)

dp[3][0] = 0   (capacidad 0, nada cabe)
dp[3][1] = 0   (capacidad 1, joya pesa 3 → no cabe → dp[2][1]=0)
dp[3][2] = 10  (capacidad 2, joya pesa 3 → no cabe → dp[2][2]=10)
dp[3][3] = max(dp[2][3]=10, dp[2][3-3]+12 = dp[2][0]+12 = 0+12 = 12) = 12
dp[3][4] = max(dp[2][4]=16, dp[2][4-3]+12 = dp[2][1]+12 = 0+12 = 12) = 16
dp[3][5] = max(dp[2][5]=16, dp[2][5-3]+12 = dp[2][2]+12 = 10+12 = 22) = 22 ✅
dp[3][6] = max(dp[2][6]=16, dp[2][6-3]+12 = dp[2][3]+12 = 10+12 = 22) = 22 ✅

Respuesta: dp[3][6] = 22

Reconstrucción — ¿qué items se tomaron?

Empezamos desde dp[3][6] = 22, fila=3, w=6

¿Vino de tomar item 3?
  dp[3][6]=22 ≠ dp[2][6]=16 → SÍ se tomó item 3 (joya)
  w = 6 - 3 = 3, fila = 2

¿Vino de tomar item 2?
  dp[2][3]=10 ≠ dp[1][3]=6 → SÍ se tomó item 2 (cámara)
  w = 3 - 2 = 1, fila = 1

¿Vino de tomar item 1?
  dp[1][1]=0 == dp[0][1]=0 → NO se tomó item 1 (laptop)

Items tomados: {cámara (p=2,v=10), joya (p=3,v=12)}
Peso total: 2+3 = 5 ≤ 6 ✓, Valor total: 22 ✅
Complejidad: O(n×W) tiempo y espacio. Para n=100 items y W=1000: solo 100.000 celdas. Fuerza bruta: 2^100 combinaciones → inviable.
Pero atención: si W es muy grande (ej: W=10^9), O(n×W) se vuelve inviable. En ese caso el problema es NP-difícil y no hay solución eficiente conocida.

📌 Ejercicio 3 — Floyd-Warshall: caminos mínimos entre todos los pares

Problema: Encontrar el camino más corto entre todos los pares de nodos.

Grafo dirigido con 4 nodos. ∞ = no hay arco directo.

Matriz de distancias inicial

De\Hacia1234
103∞7
2802∞
35∞01
42∞∞0

Ecuación de recurrencia

dist[i][j][k] = min camino de i a j usando solo nodos intermedios {1..k}

dist[i][j][k] = min(
  dist[i][j][k-1],             ← no pasar por k
  dist[i][k][k-1] + dist[k][j][k-1]  ← pasar por k
)

"¿Conviene usar k como nodo intermedio entre i y j?"

Iteración k=1 (¿conviene pasar por el nodo 1?)

dist[2][4] = min(∞, dist[2][1]+dist[1][4]) = min(∞, 8+7) = 15
dist[3][2] = min(∞, dist[3][1]+dist[1][2]) = min(∞, 5+3) = 8
dist[4][2] = min(∞, dist[4][1]+dist[1][2]) = min(∞, 2+3) = 5
dist[4][3] = min(∞, dist[4][1]+dist[1][3]) = min(∞, 2+∞) = ∞ (sin cambio)
dist[4][4] ya = 0

Iteración k=2

dist[1][3] = min(∞, dist[1][2]+dist[2][3]) = min(∞, 3+2) = 5
dist[4][3] = min(∞, dist[4][2]+dist[2][3]) = min(∞, 5+2) = 7

Iteración k=3

dist[1][4] = min(7, dist[1][3]+dist[3][4]) = min(7, 5+1) = 6
dist[2][4] = min(15, dist[2][3]+dist[3][4]) = min(15, 2+1) = 3
dist[4][4] ya = 0
dist[2][1] = min(8, dist[2][3]+dist[3][1]) = min(8, 2+5) = 7

Iteración k=4

dist[1][1] = min(0, dist[1][4]+dist[4][1]) = min(0, 6+2) = 0 (sin cambio)
dist[2][1] = min(7, dist[2][4]+dist[4][1]) = min(7, 3+2) = 5
dist[3][2] = min(8, dist[3][4]+dist[4][2]) = min(8, 1+5) = 6

Matriz final de distancias mínimas

Complejidad: O(n³) — tres loops anidados sobre los n nodos. Para n=1000 nodos: 10⁹ operaciones. Para n=100: 10⁶ → muy rápido. Dijkstra es O(n² log n) pero solo da caminos desde un nodo origen; Floyd-Warshall da todos los pares.
Detección de ciclos negativos: si después de Floyd-Warshall algún dp[i][i] < 0, el grafo tiene un ciclo de peso negativo (lo que haría el concepto de "camino mínimo" infinito).

📌 Ejercicio 4 — LCS: Longest Common Subsequence

Problema: Encontrar la subsecuencia común más larga entre "ABCBDAB" y "BDCABA".

Subsecuencia: no tiene que ser contigua, pero respeta el orden.

Ecuación de recurrencia

dp[i][j] = longitud de la LCS entre X[1..i] e Y[1..j]

Si X[i] == Y[j]:
  dp[i][j] = dp[i-1][j-1] + 1  ← coinciden, extender LCS anterior

Si X[i] != Y[j]:
  dp[i][j] = max(dp[i-1][j], dp[i][j-1])  ← mejor de ignorar uno u otro

Tabla dp

BDCABA
0000000
A0000111
B0111122
C0112222
B0112233
D0122233
A0122334
B0122344
LCS tiene longitud 4.

Reconstrucción (recorrer tabla desde dp[7][6] hacia arriba):
  dp[7][5]=4: X[7]=B, Y[5]=B → COINCIDEN → tomar B, ir a dp[6][4]
  dp[6][4]=3: X[6]=A, Y[4]=A → COINCIDEN → tomar A, ir a dp[5][3]
  dp[5][3]=2: X[5]=D, Y[3]=C → no coinciden → ir a max(dp[4][3], dp[5][2])
              dp[4][3]=2, dp[5][2]=2 → ir a dp[4][3]
  dp[4][3]=2: X[4]=B, Y[3]=C → no coinciden → ir a dp[3][3]=2 o dp[4][2]=1
              ir a dp[3][3]
  dp[3][3]=2: X[3]=C, Y[3]=C → COINCIDEN → tomar C, ir a dp[2][2]
  dp[2][2]=1: X[2]=B, Y[2]=D → no coinciden → ir a dp[1][2]=0 o dp[2][1]=1
              ir a dp[2][1]
  dp[2][1]=1: X[2]=B, Y[1]=B → COINCIDEN → tomar B, ir a dp[1][0]=0

LCS = "BCAB" (longitud 4) ✅

Nota: puede haber múltiples LCS de la misma longitud. Otra posible: "BDAB".
Complejidad: O(m×n) tiempo y espacio, donde m=|X|, n=|Y|. Para strings de longitud 1000: 10⁶ celdas — muy manejable.

📌 Ejercicio 5 — Cambio de Monedas con PD

Problema: Dar cambio de $11 con monedas {1, 3, 4} usando la mínima cantidad de monedas. (Greedy fallaba en este caso.)

Ecuación de recurrencia

dp[i] = mínima cantidad de monedas para dar cambio de valor i

Casos base:
  dp[0] = 0   (cambio de 0: 0 monedas)
  dp[i] = ∞   para i > 0 (inicialmente desconocido)

Recurrencia:
  Para cada valor i de 1 a 11:
    Para cada moneda c en {1, 3, 4}:
      Si c ≤ i:
        dp[i] = min(dp[i], dp[i - c] + 1)

Llenado de tabla

dp[0] = 0

dp[1]: probar c=1: dp[0]+1=1; c=3: no cabe; c=4: no cabe → dp[1]=1
dp[2]: probar c=1: dp[1]+1=2                              → dp[2]=2
dp[3]: probar c=1: dp[2]+1=3; c=3: dp[0]+1=1             → dp[3]=1
dp[4]: probar c=1: dp[3]+1=2; c=3: dp[1]+1=2; c=4: dp[0]+1=1 → dp[4]=1
dp[5]: probar c=1: dp[4]+1=2; c=3: dp[2]+1=3; c=4: dp[1]+1=2 → dp[5]=2
dp[6]: probar c=1: dp[5]+1=3; c=3: dp[3]+1=2; c=4: dp[2]+1=3 → dp[6]=2
dp[7]: probar c=1: dp[6]+1=3; c=3: dp[4]+1=2; c=4: dp[3]+1=2 → dp[7]=2
dp[8]: probar c=1: dp[7]+1=3; c=3: dp[5]+1=3; c=4: dp[4]+1=2 → dp[8]=2
dp[9]: probar c=1: dp[8]+1=3; c=3: dp[6]+1=3; c=4: dp[5]+1=3 → dp[9]=3
dp[10]:probar c=1: dp[9]+1=4; c=3: dp[7]+1=3; c=4: dp[6]+1=3 → dp[10]=3
dp[11]:probar c=1: dp[10]+1=4; c=3: dp[8]+1=3; c=4: dp[7]+1=3 → dp[11]=3 ✅

Respuesta: 3 monedas para dar cambio de $11.

Reconstrucción: ¿qué monedas?
  dp[11]=3 vino de c=3 o c=4 (ambas dan 3)
  Tomemos c=4: dp[7]=2, tomamos $4 → resta cambiar $7
  dp[7]=2 vino de c=3: dp[4]=1, tomamos $3 → resta cambiar $4
  dp[4]=1 vino de c=4: dp[0]=0, tomamos $4 → resta cambiar $0

Monedas: {4, 3, 4} → 4+3+4 = 11 ✅, 3 monedas

Greedy habría dado: 4+4+1+1+1 = 5 monedas ← mucho peor
PD garantiza el óptimo para cualquier conjunto de denominaciones. Greedy solo garantiza óptimo para denominaciones con la "propiedad canónica".

🧠 Quiz — Programación Dinámica

Intentá responder antes de ver la solución.

¿Cuáles son las dos condiciones para que un problema se resuelva con PD?
1. Subestructura óptima: la solución óptima del problema original está compuesta por soluciones óptimas de sus subproblemas. Si "recorto" la solución óptima, cada parte también es óptima para su subproblema.

2. Subproblemas superpuestos: al resolver el problema por recursión, los mismos subproblemas aparecen repetidamente. Si cada subproblema es único (como en D&C), PD no aporta beneficio sobre la recursión simple.
¿Por qué la mochila 0/1 necesita PD y no Greedy?
En la mochila fraccional, tomar el item de mayor ratio es siempre óptimo porque se puede ajustar la fracción. En la 0/1 no: o tomás el item entero o no. Tomar el item de mayor ratio puede "bloquear" el espacio para una combinación de items que juntos dan mayor valor total. Hay que evaluar todas las combinaciones posibles — PD lo hace eficientemente en O(n×W) usando la tabla dp[i][w].
¿Cuándo usar Floyd-Warshall y cuándo Dijkstra?
Floyd-Warshall: cuando necesitás los caminos mínimos entre todos los pares de nodos. O(n³). Funciona con pesos negativos (siempre que no haya ciclos negativos). Simple de implementar.

Dijkstra: cuando necesitás caminos mínimos desde un solo nodo origen a todos los demás. O((n+m) log n) con heap. Solo funciona con pesos no negativos. Para grafos dispersos (pocas aristas) es mucho más eficiente que Floyd.
¿Qué es la "reconstrucción" en PD y cómo se hace?
La tabla dp guarda los valores óptimos pero no directamente qué decisiones se tomaron. La reconstrucción recupera la solución (qué elementos se incluyeron, cuál es el camino, etc.).

Se hace recorriendo la tabla al revés: desde dp[n][W] (o el valor final), en cada celda preguntás "¿esta celda vino de tomar el item i o de no tomarlo?". Si dp[i][w] == dp[i-1][w], no se tomó el item i. Si dp[i][w] == dp[i-1][w-peso[i]] + val[i], sí se tomó. Ir a la celda anterior y repetir.
¿Cuál es la diferencia entre bottom-up y top-down en PD?
Bottom-up (tabulation): resolvés los subproblemas más pequeños primero y construís la solución hacia arriba. Iterativo. Sin overhead de recursión. Siempre llena toda la tabla aunque no todos los valores sean necesarios.

Top-down (memoización): escribís la recursión natural y agregás un caché. Solo calcula los subproblemas que realmente se necesitan. Puede ser más fácil de razonar pero tiene overhead de recursión y puede causar stack overflow para n grande.
¿Cómo se detecta si un problema tiene subestructura óptima?
Una técnica: suponé que tenés la solución óptima del problema. "Cortala" quitando la primera o última decisión. ¿La parte restante es óptima para el subproblema correspondiente? Si sí → hay subestructura óptima.

Ejemplo — mochila: si la solución óptima incluye el item k, entonces los items restantes deben ser la solución óptima para capacidad W-peso[k] con los demás items. Si hubiera mejor solución para ese subproblema, podría mejorar la solución completa — contradicción. ✓ Hay subestructura óptima.
