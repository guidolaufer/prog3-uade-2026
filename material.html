⏱️ Complejidad Temporal — Base de todo

Antes de ver las técnicas, hay que entender cómo medimos la eficiencia de un algoritmo. Usamos la notación O grande que describe cómo crece el tiempo de ejecución en función del tamaño de la entrada n.

NotaciónNombreEjemplon=1000 → ops aprox.
O(1)ConstanteAcceder un array[i]1
O(log n)LogarítmicaBúsqueda binaria10
O(n)LinealRecorrer un array1.000
O(n log n)Log-linealMergeSort, HeapSort10.000
O(n²)CuadráticaBubbleSort, inserción1.000.000
O(2ⁿ)ExponencialSubconjuntos, fuerza bruta~10³⁰⁰
O(n!)FactorialPermutacionesimposible
Regla práctica: Dos loops anidados → O(n²). Un loop que divide a la mitad → O(log n). Un loop + dividir a la mitad → O(n log n).

📐 Teorema Maestro — para recursiones D&C

Cuando un algoritmo se expresa como: T(n) = a·T(n/b) + f(n)

donde a = nº subproblemas, b = factor de división, f(n) = costo de combinar

CasoCondiciónResultadoEjemplo
Caso 1f(n) = O(n^(log_b(a) − ε))T(n) = Θ(n^log_b(a))T(n)=8T(n/2)+n → O(n³)
Caso 2f(n) = Θ(n^log_b(a))T(n) = Θ(n^log_b(a) · log n)T(n)=2T(n/2)+n → O(n log n)
Caso 3f(n) = Ω(n^(log_b(a) + ε))T(n) = Θ(f(n))T(n)=2T(n/2)+n² → O(n²)
MergeSort: T(n) = 2T(n/2) + n → a=2, b=2, log₂2=1, f(n)=n=Θ(n¹) → Caso 2 → O(n log n)

✂️ Divide & Conquer

La idea central es simple: si el problema es grande, dividilo en partes más chicas, resolé cada parte recursivamente, y combiná los resultados.

✅ Cuándo usarlo
El problema se puede dividir en subproblemas independientes del mismo tipo. Los subproblemas no se superponen.
❌ Cuándo NO usarlo
Los subproblemas se repiten muchas veces (ahí usás PD). El costo de combinar supera el ahorro de dividir.
1
DIVIDIR Partís el problema en a subproblemas de tamaño n/b. Normalmente a=2, b=2 (dos mitades).
2
CONQUISTAR Resolvés cada subproblema recursivamente. Caso base: cuando n es suficientemente pequeño, resolvés directamente.
3
COMBINAR Juntás las soluciones parciales para obtener la solución del problema original. Este paso suele ser O(n).

📌 Ejemplo 1 — MergeSort

Ordenar el arreglo: [38, 27, 43, 3, 9, 82, 10]

DIVIDIR:
[38,27,43,3,9,82,10]
    ↙              ↘
[38,27,43]      [3,9,82,10]
  ↙    ↘          ↙      ↘
[38] [27,43]   [3,9]   [82,10]
      ↙  ↘     ↙  ↘     ↙   ↘
     [27][43]  [3] [9]  [82] [10]

CONQUISTAR (ya son de tamaño 1, están "ordenados"):
[27] [43] → merge → [27,43]
[3]  [9]  → merge → [3,9]
[82] [10] → merge → [10,82]

COMBINAR:
[38] + [27,43] → merge → [27,38,43]
[3,9] + [10,82] → merge → [3,9,10,82]
[27,38,43] + [3,9,10,82] → merge → [3,9,10,27,38,43,82] ✅
¿Cómo funciona el merge? Comparás el primer elemento de cada mitad, ponés el menor en el resultado, avanzás en esa mitad. Repetís hasta vaciar ambas. Costo: O(n).
Complejidad MergeSort: T(n) = 2T(n/2) + O(n) → O(n log n) siempre (mejor, peor y promedio caso).

📌 Ejemplo 2 — Máximo Subarreglo (D&C)

Dado un arreglo con negativos, encontrar el subarreglo contiguo de suma máxima.

Ej: [-2, 1, -3, 4, -1, 2, 1, -5, 4] → respuesta: [4,-1,2,1] = 6

Dividir en mitad: izq=[-2,1,-3,4] der=[-1,2,1,-5,4]
Tres casos posibles para el subarreglo máximo:
  1. Está completamente en la mitad izquierda
  2. Está completamente en la mitad derecha
  3. Cruza el punto medio (abarca parte de ambas mitades)

Para el caso 3 (cruce):
  Desde el centro hacia la izquierda: max que termina en el centro
  Desde el centro hacia la derecha: max que empieza en el centro+1
  Suma de ambos = subarreglo cruzado máximo

Resultado = máximo de los 3 casos.
Nota: Para este problema, el algoritmo de Kadane (O(n), lineal) es más eficiente que D&C (O(n log n)). En el parcial pueden preguntar ambos y pedirte que compares.

📌 Ejemplo 3 — Búsqueda Binaria

Buscar x en arreglo ordenado A[0..n-1]:
  mid = (low + high) / 2
  si A[mid] == x → encontrado
  si A[mid] > x  → buscar en A[low..mid-1]  (mitad izquierda)
  si A[mid] < x  → buscar en A[mid+1..high] (mitad derecha)

T(n) = T(n/2) + O(1) → O(log n)
Con un arreglo de 1.000.000 elementos, la búsqueda lineal necesita hasta 1.000.000 comparaciones. La búsqueda binaria: ≤ 20 comparaciones.

💰 Algoritmos Greedy (Voraces)

Un algoritmo greedy toma siempre la decisión localmente óptima en cada paso, esperando que esto lleve a la solución globalmente óptima.

✅ Cuándo funciona
El problema tiene propiedad greedy: la elección local óptima es parte de la solución global óptima. Ej: mochila fraccional, Huffman, Kruskal.
❌ Cuándo NO funciona
Mochila 0/1 (no fraccional), cambio de monedas con denominaciones arbitrarias. Greedy puede dar solución subóptima.
1
Elegir el mejor candidato disponible Según algún criterio de selección (mayor valor, menor costo, mayor ratio, etc.).
2
Verificar factibilidad ¿Se puede incluir sin violar las restricciones? Si sí, incluirlo. Si no, descartarlo (nunca se reconsidera).
3
Repetir hasta completar la solución Greedy nunca vuelve atrás.

📌 Ejemplo 1 — Cambio de Monedas

Dar cambio de $41 con monedas de $25, $10, $5, $1.

Greedy: siempre tomar la moneda más grande posible.
41 → tomo 25 → resta 16
16 → tomo 10 → resta 6
 6 → tomo  5 → resta 1
 1 → tomo  1 → resta 0
Resultado: 25+10+5+1 = 4 monedas ✅

⚠️ Pero si las monedas fueran {1, 3, 4} y queremos cambiar 6:
Greedy: 4 + 1 + 1 = 3 monedas
Óptimo: 3 + 3 = 2 monedas ← Greedy falla aquí
Lección: Greedy funciona para monedas del sistema decimal estándar (25,10,5,1). Con denominaciones arbitrarias, puede fallar. En esos casos hay que usar Programación Dinámica.

📌 Ejemplo 2 — Mochila Fraccional

Items con peso y valor. La mochila soporta W=50 kg. Se puede tomar fracciones.

ItemPeso (kg)Valor ($)Ratio ($/kg)
A10606.0 ★
B201005.0
C301204.0
Greedy: ordenar por ratio descendente, tomar todo lo que quepa.
→ Tomar A completo (10kg, $60). Resta: 40kg
→ Tomar B completo (20kg, $100). Resta: 20kg
→ Tomar 20/30 de C (20kg, $80). Resta: 0kg
Valor total = 60 + 100 + 80 = $240 ✅ ÓPTIMO
La mochila fraccional tiene solución óptima con Greedy por ratio. La mochila 0/1 (sin fracciones) NO — ahí se usa Programación Dinámica.

📌 Ejemplo 3 — Código de Huffman

Compresión de datos. Asignar códigos binarios más cortos a los caracteres más frecuentes.

Frecuencias: a=5, b=9, c=12, d=13, e=16, f=45

1. Crear un nodo hoja por cada carácter con su frecuencia.
2. Repetir hasta tener 1 solo árbol:
   - Tomar los 2 nodos de menor frecuencia
   - Crear nodo padre con suma de sus frecuencias
   - Insertar en la cola de prioridad

Árbol resultante (frecuencias):
        100
       /    \
     45(f)   55
            /   \
          25     30
         / \    /  \
       12(c) 13(d) 14  16(e)
                  / \
                5(a) 9(b)

Códigos: f=0, c=100, d=101, a=1100, b=1101, e=111
Los más frecuentes (f,e) tienen códigos más cortos ✅
Huffman es óptimo — ningún otro código prefijo de longitud variable puede comprimir más con estas frecuencias. Complejidad: O(n log n).

🔙 Backtracking

Backtracking es una forma de fuerza bruta inteligente. Explorás todas las posibilidades, pero cuando detectás que una rama no puede llevar a solución, la podás (no seguís explorando por ahí).

✅ Cuándo usarlo
Problemas de decisión o búsqueda donde hay que explorar combinaciones. N-Reinas, Sudoku, subconjuntos, coloreo de grafos.
🐢 Desventaja
Peor caso exponencial O(2ⁿ) o O(n!). La poda es clave para que sea práctico. Sin poda = fuerza bruta pura.
1
Elegir un candidato Para la posición actual, elegí un valor posible.
2
Verificar validez (poda) ¿Es válido incluirlo? Si viola alguna restricción → descartarlo y probar el siguiente.
3
Avanzar recursivamente Si es válido, agregarlo a la solución parcial y continuar con la siguiente posición.
4
Deshacer (backtrack) Si llegaste a un punto sin solución, retirar el último candidato y probar el siguiente.

📌 Ejemplo 1 — N-Reinas (4 reinas)

Colocar 4 reinas en un tablero 4x4 sin que se ataquen.

Representación: sol[i] = columna donde va la reina de la fila i

Fila 1: probar columna 1 → colocar reina en (1,1)
  Fila 2: col 1 → ataque vertical ✗
          col 2 → ataque diagonal ✗
          col 3 → válido → colocar en (2,3)
    Fila 3: col 1 → ataque diagonal ✗
            col 2 → ataque diagonal ✗
            col 3 → ataque vertical ✗
            col 4 → ataque diagonal ✗
            → SIN SOLUCIÓN → backtrack a Fila 2
  Fila 2: col 4 → válido → colocar en (2,4)
    Fila 3: col 2 → válido → colocar en (3,2)
      Fila 4: col 1 → ataque diagonal ✗
              col 2 → ataque vertical ✗
              col 3 → ataque diagonal ✗
              col 4 → ataque diagonal ✗
              → backtrack a Fila 3
    Fila 3: col 3 → ataque diagonal ✗
            → backtrack a Fila 2
  → backtrack a Fila 1, probar columna 2...

Una solución: (1,2), (2,4), (3,1), (4,3) ✅
Q . . .       . Q . .       . . Q .       . . . Q
. . . Q  →   . . . Q  →  correctamente distribuidas
. . Q .
. Q . .
Función de poda: dos reinas se atacan si están en la misma columna, misma fila, o misma diagonal. Diagonales: |fila1-fila2| == |col1-col2|.

📌 Ejemplo 2 — Subconjuntos con Suma Objetivo

Encontrar todos los subconjuntos de {3,5,6,7} que sumen 15.

Árbol de decisión (incluir o no incluir cada elemento):

                    {}
              ┌─────┴─────┐
            {3}           {}
          ┌──┴──┐       ┌──┴──┐
        {3,5}  {3}    {5}    {}
       suma=8  ...   suma=5  ...
      ┌──┴──┐
   {3,5,6} {3,5}
   suma=14 ...
  ┌────┴────┐
{3,5,6,7} {3,5,6}
suma=21✗  suma=14✗

Poda: si suma parcial > 15, no seguir por esa rama.
Solución encontrada: {3,5,7}=15 ✅, {8,7}=15 (si 8 fuera elem.)

Para {3,5,6,7}: {3,5,7}=15 ✅

📊 Programación Dinámica (PD)

La idea central: guardar los resultados de subproblemas para no recalcularlos. Se usa cuando los subproblemas se superponen (mismo subproblema aparece muchas veces).

✅ Condiciones para usar PD
Subestructura óptima: la solución óptima del problema contiene soluciones óptimas de subproblemas.
Subproblemas superpuestos: el mismo subproblema se resuelve muchas veces.
PD vs D&C
D&C: subproblemas independientes (no se repiten) → recursión simple.
PD: subproblemas superpuestos → memoización o tabla bottom-up.
1
Definir la estructura de la solución óptima ¿Cómo se relaciona la solución de tamaño n con soluciones de tamaños menores?
2
Definir la ecuación de recurrencia dp[i] = f(dp[i-1], dp[i-2], ...). Esta es la parte más importante.
3
Inicializar casos base Los valores de dp para los casos más pequeños (dp[0], dp[1], etc.).
4
Llenar la tabla bottom-up Calcular dp[i] en orden, usando los valores ya calculados.
5
Reconstruir la solución (si hace falta) Usar la tabla para rastrear qué decisiones se tomaron.

📌 Ejemplo 1 — Fibonacci

Recursión ingenua: O(2ⁿ)     PD: O(n)

fib(5) → fib(4) + fib(3)
fib(4) → fib(3) + fib(2)   ← fib(3) se recalcula
fib(3) → fib(2) + fib(1)   ← fib(2) se recalcula varias veces

Con PD (tabla):
dp[0]=0, dp[1]=1
dp[2]=dp[1]+dp[0]=1
dp[3]=dp[2]+dp[1]=2
dp[4]=dp[3]+dp[2]=3
dp[5]=dp[4]+dp[3]=5  ✅ Solo 5 operaciones vs 15 con recursión

📌 Ejemplo 2 — Mochila 0/1

Items: {(peso=2,val=3), (peso=3,val=4), (peso=4,val=5), (peso=5,val=6)}. Capacidad W=5.

dp[i][w] = máximo valor usando los primeros i items con capacidad w

Recurrencia:
  Si peso[i] > w:  dp[i][w] = dp[i-1][w]   (no cabe, no tomar)
  Si peso[i] ≤ w:  dp[i][w] = max(dp[i-1][w],
                                   dp[i-1][w-peso[i]] + val[i])

Tabla (filas=items, columnas=capacidad 0..5):
     W=0  W=1  W=2  W=3  W=4  W=5
i=0   0    0    0    0    0    0
i=1   0    0    3    3    3    3   (item1: p=2,v=3)
i=2   0    0    3    4    4    7   (item2: p=3,v=4)
i=3   0    0    3    4    5    7   (item3: p=4,v=5)
i=4   0    0    3    4    5    7   (item4: p=5,v=6)

Respuesta: dp[4][5] = 7 ✅
(tomar item1 (p=2,v=3) + item2 (p=3,v=4) = peso 5, valor 7)
Complejidad Mochila 0/1: O(n·W) en tiempo y espacio. Para W grande → puede ser lento (problema NP).

📌 Ejemplo 3 — Floyd-Warshall

Encontrar el camino más corto entre todos los pares de nodos en un grafo.

dist[i][j][k] = camino más corto de i a j usando solo nodos 1..k

Recurrencia:
  dist[i][j][k] = min(dist[i][j][k-1],
                      dist[i][k][k-1] + dist[k][j][k-1])
  "¿Conviene pasar por el nodo k?"

Ejemplo: grafo con 4 nodos
     1→2: 5  1→3: ∞  1→4: 10
     2→3: 3  2→4: ∞  3→4: 1
     (+ arcos inversos si no dirigido)

Iteración k=3 (¿conviene pasar por nodo 3?):
  dist[1][4] = min(10, dist[1][3]+dist[3][4]) = min(10, ∞+1) = 10
  → con k=3: dist[1][2]+dist[2][3]=5+3=8 para 1→3
  → luego dist[1][4] = min(10, 8+1) = 9 ✅

Complejidad: O(n³)

¿Cuál es la diferencia entre D&C y Programación Dinámica?
En D&C, los subproblemas son independientes entre sí — al resolver uno, no necesitamos el resultado del otro para calcular el primero. En PD, los subproblemas se superponen: el mismo subproblema aparece varias veces. PD lo resuelve una sola vez y guarda el resultado (memoización o tabla). D&C típicamente no guarda resultados.
¿Cuándo Greedy garantiza la solución óptima?
Cuando el problema tiene la propiedad de elección greedy: la elección localmente óptima en cada paso es parte de alguna solución globalmente óptima. Esto se demuestra formalmente (por intercambio o por inducción). Sin esta demostración, Greedy puede dar resultados subóptimos. Ejemplos donde funciona: mochila fraccional, Huffman, Kruskal, Dijkstra. Donde NO funciona: mochila 0/1, cambio con monedas arbitrarias.
¿Qué es la poda en Backtracking y por qué es importante?
La poda es el mecanismo que permite descartar ramas enteras del árbol de búsqueda cuando se detecta que no pueden llevar a una solución válida. Sin poda, backtracking = fuerza bruta pura (explora todo). Con buena poda, se puede reducir drásticamente el espacio de búsqueda. Ejemplo: en N-Reinas, si una reina en (1,1) ya ataca a cualquier candidato en fila 2, no tiene sentido explorar ninguna posición en fila 2 sin mover la reina de fila 1.
¿Cuáles son las condiciones para aplicar Programación Dinámica?
Dos condiciones necesarias:
1. Subestructura óptima: la solución óptima del problema original contiene soluciones óptimas de sus subproblemas. Si puedo "cortar" la solución óptima y cada parte también es óptima para su subproblema, hay subestructura óptima.
2. Subproblemas superpuestos: al resolver el problema por recursión, los mismos subproblemas aparecen repetidamente. Si cada subproblema es único (como en D&C), PD no agrega valor.
¿Qué es el Teorema Maestro y cuándo se aplica?
El Teorema Maestro da la complejidad de recursiones de la forma T(n) = a·T(n/b) + f(n), donde a ≥ 1, b > 1, y f(n) es la función de costo de combinar. Se compara f(n) con n^(log_b(a)):
• Si f crece más lento → el árbol de recursión domina → O(n^log_b(a))
• Si son iguales → O(n^log_b(a) · log n)
• Si f crece más rápido → la raíz domina → O(f(n))
No aplica si a o b no son constantes, o si la recursión no tiene esa forma.
¿Por qué MergeSort es O(n log n) y BubbleSort es O(n²)?
MergeSort divide el array a la mitad en cada nivel (log n niveles) y en cada nivel hace O(n) trabajo total de merge → O(n log n).
BubbleSort tiene dos loops anidados: para cada uno de los n elementos, en el peor caso compara con los n-1 restantes → O(n²). La diferencia es enorme: para n=1.000.000, MergeSort hace ~20M operaciones y BubbleSort haría 10¹² operaciones.
¿Por qué la mochila fraccional se resuelve con Greedy pero la 0/1 necesita PD?
En la mochila fraccional, siempre conviene tomar el item con mayor ratio valor/peso, porque se puede tomar cualquier fracción. La elección greedy local es óptima.
En la mochila 0/1, no se puede fraccionar: o tomás el item entero o no lo tomás. Una elección greedy puede bloquear items que juntos darían mayor valor. Se necesita PD para evaluar todas las combinaciones de forma eficiente.
¿Qué es la memoización y en qué se diferencia del approach bottom-up de PD?
Memoización (top-down): escribís la recursión natural y guardás cada resultado calculado en un diccionario/array. Solo calculas los subproblemas que realmente necesitás. Más fácil de implementar pero tiene overhead de recursión.
Bottom-up: llenás la tabla de subproblemas desde los más pequeños hasta el más grande, sin recursión. Más eficiente en práctica, sin stack overflow. La tabla siempre existe completa aunque no todos los valores se necesiten.
